## 0. 한 줄 요약

브랜드 태그 게시물 수집을 "매일 전량(90일 & 105개)"에서 **게시물 나이 기반 티어 주기 +
등록 시 12개월 백필**로 바꾼다. 티어는 저장 상태 없이 `taken_at`·`last_crawled_at`만으로
매 실행 시 순수 함수 판정하고, 페이지 단위 태그 열거의 특성에 맞춰 **"오늘의 열거 깊이"로
번역**해 적용한다. 스키마 변경은 `brand_tagged_post.last_crawled_at` 컬럼 1개 추가가 전부다.

## 2. 핵심 제약 — 티어를 "열거 깊이"로 번역하는 이유

수집 경로는 태그 열거(`/v2/user/tag/medias`, 페이지당 실측 21건, **태그된 시점 순**) 단일
경로다. "이 게시물 하나만 다시 크롤"이라는 동작이 존재하지 않는다 — 특정 게시물을 갱신하려면
그 게시물이 나올 때까지 페이지를 넘겨야 한다. 따라서:

- 티어 판정은 게시물 단위(순수 함수)로 하되, 실행은 **브랜드 단위 "오늘의 열거 깊이"**로 한다.
- 깊은 열거는 얕은 구간을 자동 포함한다 → 정책의 "상위 범위 크롤이 하위 포함, 중복 제거"가
  구조적으로 성립한다(별도 스킵 로직 불필요).
- 열거에서 만난 게시물은 due 여부와 무관하게 전부 적재한다 — 페이지에 실려 온 지표는 콜 0
  추가의 공짜 데이터라 버릴 이유가 없다.

## 3. 티어 판정 — `BrandCrawlPolicy` (신규 순수 함수 컴포넌트)

입력은 `taken_at`·`last_crawled_at`·현재 시각 3개. 저장된 티어 상태 없음(정책 원칙).

```
age = now - taken_at

age ≤ 14일          → 스윕마다 due (매일)
14일 < age ≤ 30일   → now - last_crawled_at ≥ 3일이면 due
30일 < age ≤ 90일   → ≥ 7일이면 due
90일 < age ≤ 180일  → ≥ 30일이면 due
age > 180일         → 영구 제외 (발견 시 스냅샷 1회로 종료)

last_crawled_at = null → 무조건 due (마이그레이션 직후 기존 행·미완 수집분 안전 수렴)
```

- 판정 기준은 항상 `taken_at`(게시물 나이)이다 — 발견 시각이 아니다. 늦게 발견된 게시물은
  나이에 맞는 티어로 바로 진입하고, 초기 추이 부재는 `first_seen_at`(= 정책의 `detected_at`)
  으로 투명하게 표기한다(추정치로 채우지 않음 — 데이터 정직성 원칙).
- 티어 경계·주기는 정책 상수로 코드에 둔다(런타임 토글 불필요 — YAGNI). v1.1 변화율 기반
  적응형 조정이 오면 이 컴포넌트만 바뀐다.

## 4. 매일 스윕 — 깊이 결정과 중단 규칙

브랜드마다 매일 1회(현행 스케줄 유지):

1. `brand_tagged_post`에서 due 게시물을 §3 판정식으로 조회한다.
2. **열거 깊이 컷 = min(now − 14일, 가장 오래된 due 게시물의 taken_at)** — due가 없어도
   신규 태그 발견을 위해 최소 14일 깊이는 매일 보장한다.
3. 현행과 같은 열거 루프: 컷까지 `next_page_id` 추종, 중단 조건은 ①페이지 전체가 컷 이전
   (소급 태그 혼입 때문에 "오래된 글 1건 발견 즉시 중단" 금지 — 08-06 스펙 §5 유지)
   ②커서 소진 ③커서 미전진 ④안전 상한 도달(§6).
4. 만난 게시물 전부(아래 편입 규칙의 ">365일 무시" 대상 제외): 스냅샷 적재(복권 보정 포함)
   + `last_crawled_at` 갱신. 신규 code는 링크(`first_seen_at` 자동 기록). 이미 종료된
   180일 초과 게시물도 깊은 크롤에 우연히 실려 오면 스냅샷은 적재한다 — 콜 0 추가의 공짜
   데이터고, due 판정(§3)이 영구 제외라 이들을 위한 콜은 여전히 발생하지 않는다.
5. 보강(게시자 프로필·댓글 게이트)은 이번 스윕에서 만난 게시물 대상 — 현행 의미 그대로.

**신규 발견 게시물의 편입 규칙** (열거 정렬이 태그 시점 순이라 옛 게시물이 최신 페이지에
끼어드는 소급 태그 포함):

| 발견 시점 나이 | 처리 |
|---|---|
| ≤ 180일 | 링크 + 스냅샷 → §3 티어로 추적 |
| 180~365일 | 링크 + 스냅샷 1회로 종료 (정책의 6~12개월 스냅샷 구간) |
| > 365일 | 무시 (정책 §2 최대 12개월) |

**자가 치유**: 스윕이 하루 실패해도(브랜드 단위 격리·백스톱 현행 유지) due 판정이
`last_crawled_at` 기반이라 다음 스윕이 밀린 깊이까지 자동 커버한다. 별도 보정 없음.

## 5. 등록 백필

- 현행과 같은 코드(`sweepCore`) — 컷만 90일 → **365일**, 105개 상한 폐지(정책: "기존 3개월
  or 105개 제한은 폐지"). cclime_official 실측 847개 기준 열거 ~41콜.
- 단계식 ready(core 즉시 `touchSwept` → 보강 별도 executor)·실패 격리·백스톱은 2026-08-07
  결정 그대로.
- 등록 시 나이 180일 초과 게시물은 그 자리에서 스냅샷 1회를 확보하고 티어 추적 대상에서
  영구 제외된다(§3 판정식이 자동 처리 — 별도 분기 없음).

## 6. 스키마·설정 변경

**마이그레이션 (expand, UTC 타임스탬프 채번):**

```sql
ALTER TABLE brand_tagged_post ADD COLUMN last_crawled_at timestamptz;
```

- 기존 행은 null 유지 → "null = 무조건 due" 규칙으로 첫 스윕에서 자연 수렴(백필 UPDATE 불필요).
- 정책의 "reposts/saves/shares nullable 선반영"은 `brand_post_snapshot`에 이미 존재.
  수집 타임스탬프는 `captured_on`이 담당 — 추가 컬럼 없음.

**설정 교체 (`monitoring.brand.*`):**

| 제거 | 신설 | 의미 |
|---|---|---|
| `window-days` (90) | `registration-window-days` (365) | 등록 백필·신규 편입 컷 |
| `window-posts` (105) | `max-posts-per-sweep` (2000) | 개수 상한 폐지, 폭주 방어용 안전 밸브만(도달 시 경고 로그 — 정상 경로에서 닿으면 안 되는 값) |

`comment-pages`(3)·`author-stale-days`(30)는 그대로.

## 7. 변경하지 않는 것 (확정 사항의 명시적 재확인)

- **단건 게시물 콜 전면 금지** — 08-06 실측 근거 유지.
- **복권 3종 열거 기회 적재 + FE 미노출** — 부재=0·0 캐리 규칙(DECISIONS 08-05) 포함 그대로.
- **댓글 게이트** — `comment_count` 증가 시에만 최대 3콜(45개), 기지 댓글 중단. 깊은 티어
  크롤에서 게시물이 재등장할 때(3일/7일/30일 간격) 증가분을 자동 수집 — 30일 보충 없음.
- **게시자 프로필** — 등장 시 30일 stale 갱신, 브랜드 간 전역 캐시.
- **브랜드 프로필 매일 1콜** + 추이 일 1행, best-effort 격리.
- **실패 격리·백스톱 구조** — 브랜드 단위 격리, `last_swept_on` 백스톱, 워커 풀(동시 6) 병렬화.

## 9. 테스트

- `BrandCrawlPolicy` 단위 테스트: 티어 경계값(14/30/90/180일) ± 주기 경계, `last_crawled_at`
  null, 자가 치유(스윕 공백 후 due 판정) 케이스.
- `BrandCollectService` 테스트: due 기반 깊이 결정, 최소 14일 깊이 보장, 중단 규칙(안전 상한
  포함), 늦은 발견 편입 3분기(≤180일 / 180~365일 / >365일), 기존 행 null 수렴.
- 기존 모듈 테스트 관용구(Testcontainers·격리 규칙) 따름.
