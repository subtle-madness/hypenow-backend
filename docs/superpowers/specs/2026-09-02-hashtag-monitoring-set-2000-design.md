# 해시태그 감시 세트 2,000 롤링 전환 설계

> 상태: 🟢 활성 · 2026-09-02 승인(사용자 구두 승인, 구현 전)

## 0. 배경 — 09-02 미처리 1,828건 진단

성과 대시보드 "오늘 게시물 갱신 — 티어별"의 매일 티어 미처리 1,828건을 추적한 결과
(celimax.korea 586 · celimax.global 609 · mom.twins_official 461 · aestura.official 77 · kayali 76):

- 미처리 행은 **전원 해시태그 편입 행**(tagged 아님)이었다. 태그 피드 열거·깊이 touch의
  대상이 아니고 2단계 단건 재수집(`unenumerated-sweep-limit: 300`) 담당인데, 이 브랜드들의
  일일 due(355~933건)가 상한 300을 매일 초과해 꼬리가 구조적으로 밀렸다(로그 INFO
  "2단계 단건 수집 상한(300) 컷" 5건으로 확정).
- 별개로 **celimax.korea·celimax.global은 해시태그 편입 상한(`hashtag.post-limit: 1000`)에
  정확히 도달**해 있어, 신규 해시태그 게시물이 편입되지 못하고 버려지는 중이다.
- 대시보드 "미처리 브랜드별" 판독("피드 훑기가 중간에 끊김")은 태그 피드 실패 전제라
  이 케이스를 오진한다.

## 1. 결정 — 출처별 독립 감시 세트, 해시태그도 태그드처럼

**브랜드당 감시 세트는 출처별로 독립**이며, 해시태그를 태그드와 같은 "최신 N 롤링" 의미론으로
전환한다. 밀려난 행은 재방문하지 않되 저장·서빙은 유지한다(지표 동결 — 태그드 기존 의미론과
동일).

| 출처 | 현재 | 변경 후 |
|---|---|---|
| 태그드 | 최신 2,000 롤링(`collection-post-limit`) | 변경 없음 |
| 해시태그 | 1,000 하드스톱 — 차면 신규 편입 중단(드랍) | **최신 2,000 롤링** — 신규 항상 편입, 게시일 기준 2,000 밖 행은 동결 |
| 직접 등록 | 상한 없음(건수 미미) | 변경 없음 — 항상 갱신 대상 |

기각한 대안: 출처 합산 단일 2,000 예산(태그드·해시태그 상호 잠식이 생겨 기각 —
사용자 확정 2026-09-02), 갱신 상한 유지·점진 상환(미처리 밀림이 구조적으로 지속돼 기각).

## 2. 편입·첫 수집

- **하드스톱 폐기**: `post-limit` 도달 시 신규 편입 중단 규칙을 제거한다. 편입은 항상
  수행하고(수집 창 `collectionCutoff` 필터는 유지), 감시 세트 판정("해시태그 성분 행 중
  게시일 최신 2,000")이 갱신 대상을 정한다. 태그 간 공유 예산 의미는 유지된다 —
  태그1이 세트를 1,800건 채우면 태그2·3의 백필은 잔여 200건에서 끊긴다.
- **신규 태그 백필**: 태그당 `max-pages: 4`(~100건) 제한을 **예산 기반 종료**로 교체한다 —
  잔여 세트 예산 소진, dedup 도달, 스트림 소진 중 먼저 오는 것까지. `max-pages`는 폭주
  방어 안전 밸브로 남기고 상향한다(기본 100 — 2,000건 ≈ 85페이지 여유).
- **배포 후 1회 딥 재열거**: 하드스톱 기간에 버려진 게시물은 dedup 조기 종료(페이지에
  기존 행이 보이면 중단) 때문에 증분 스윕으로는 영영 회수되지 않는다. 상한 상향 직후
  태그별 1회에 한해 dedup 종료를 무시하고 예산까지 열거하는 재백필을 돌린다(신규 태그
  백필과 같은 경로 재사용). recent 스트림이 옛 게시물을 어디까지 돌려주는지는 보장이
  없으므로 회수는 best-effort다.

## 3. 재수집(2단계) — "정책대로"가 실제로 성립하게

- 2단계 단건 재수집 모수 = **감시 세트 안의 해시태그 행 ∪ 직접 등록 행**. 기존 겹침 구제
  규칙(태그드 성분이 같이 있는 행도 포함)은 유지하고, 세트 순위는 해시태그 성분 행의
  게시일 내림차순으로 센다. 나이 티어 정책(`BrandCrawlPolicy.due`)은 그대로.
- `unenumerated-sweep-limit`: 300 → **2,000**. 세트 크기가 자연 상한이므로 사실상 안전
  밸브 역할이다.
- **동결 touch**: 세트 밖으로 밀려난 해시태그 행에는 태그드의 "커버 간주 touch"
  (`touchCrawledDepth` 관용구)와 같은 의미로 `last_crawled_at`을 1회 찍는다. 안 찍으면
  밀려난 행의 due가 영구 재장전돼 대시보드 미처리에 매일 누적되고, 2단계 정렬·조회를
  오염시킨다(태그드가 같은 이유로 깊이 touch를 두는 것과 동형).

## 4. 노출 상한 제거 (was)

- `BrandCollectionCap.POST_LIMIT`(2,000) 서빙 컷을 폐지한다 — 링크 창 필터를 통과한
  전량(동결분 포함)을 서빙. `meta.collectionCapped`는 FE 호환을 위해 필드는 유지하되
  항상 false로 내린다(제거는 FE 전환 확인 후).
- 성능: aestura급(창 안 3,900건+)은 응답 모수가 ~2배가 된다. 브랜드 목록 고정비가 JDBC
  행 매핑이라는 08-28 실측이 있으므로, 구현 시 실데이터로 응답 시간을 확인하고 필요하면
  후속 트랙으로 분리한다.
- 프론트 "클로즈 베타는 최대 2,000개까지 수집합니다" 문구는 FE 소관 수정 대상으로 남긴다.

## 5. 대시보드 정합 (부수 수정)

"미처리 브랜드별"·"오늘 게시물 갱신 — 티어별" 패널의 due 집계가 해시태그·직접 행을
태그 피드 커버리지와 뭉뚱그리는 문제를 고친다 — 미처리를 출처별로 분리 표기하고, 해시태그
잔여의 판독을 "2단계 상한 컷/감시 세트 밖 동결"로 구분한다. §3의 동결 touch가 들어가면
동결 행은 due에서 자연히 빠지므로, 패널 수정의 본체는 출처 분리 표기다.

## 6. 비용

- **일일 갱신**: 캠페인 피크(최근 14일 게시물이 세트 대부분) 기준 브랜드당 하루
  ~1,000~2,000콜 ≈ $0.7~1.4/일 ≈ 월 $20~40/브랜드(Hiker 실단가 $0.00069). 게시물이
  14일을 넘겨 3일/7일 티어로 내려가면 자연 감소. 현행 300콜(~$0.2/일) 대비 증가분은
  사용자 승인됨(2026-09-02).
- **등록 백필**: 빈 브랜드에 대형 태그 등록 시 열거 ~85콜 + 보강(게시자 프로필·댓글
  3콜/건) 최대 ~8,000콜 ≈ $5~6/태그.
- **1회 딥 재열거**(§2): 브랜드당 회수분 보강 포함 ~$3 수준, 1회성.
