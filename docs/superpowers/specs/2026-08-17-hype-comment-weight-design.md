# 하입 스코어 댓글 가중 하향 설계 (v3.2 — 댓글 ×3 → ×1.5, 설정화)

> 상태: ✅ 구현됨(2026-08-17) — 배포는 develop→staging→main 승격으로

## 1. 배경 — 발굴 랭킹 1위 고착 진단 (2026-08-17 실측)

"지금 뜨는 인플루언서"(발굴 목록, 기본 정렬 `avg_hype_score_precise`) 1위가 2~3주째
동일 계정(`beauty_linyas2`, 팔로워 866)으로 고착됐다. 운영 raw DB에서 창(최근 12개)을
콘텐츠별로 분해한 결과, 고착의 주인은 **댓글 ×3 가중**이었다:

- 이 계정은 전 게시물에서 댓글 수 ≈ 좋아요 수(29:35, 43:41, 88:90 …). 통상 댓글은
  좋아요의 수 % 수준이므로 품앗이·답글 위주 패턴으로 추정된다.
- 참여 항 `(likes + comments×3)/(followers+1000)`에서 이 계정 피드 게시물의 분자
  ~78%가 댓글×3 몫이다. 조회수 없는 피드(좋아요 29·댓글 35)가 출력 93.1점을 받았다.
- 반면 2위(`soft.lynaomi`)는 평균 조회 1.6만·13.8만 바이럴 릴을 보유하고도 계정 raw
  91.2 vs 93.97로 밀렸다 — 실조회 실적이 댓글 패턴을 못 이기는 구조.

보조 요인(이번 범위 밖): ① 초다작(창 12개가 6일 안, 감쇠 무력화 — 게시 빈도 반영은
명시된 제품 결정), ② 이중 상단 매핑의 점수 압축(상위 10이 98.6~99.8 밀집 — 순위에는
영향 없음).

## 2. 결정

**댓글 가중을 ×3 → ×1.5로 낮추고, 가중을 app_setting 키로 설정화한다.**

- 방식 선택(사용자 결정): 단순 하향 ×1도, 비율 캡 병행도 아닌 **중간값 하향** —
  "댓글은 좋아요보다 진한 신호"라는 원 취지를 일부 보존한다.
- 값 선택(사용자 결정, 운영 시뮬레이션 근거): w ∈ {3, 2, 1.5} 동시 시뮬레이션 결과
  ×2는 1위 마진을 2.77 → 0.30으로 줄이지만 순위를 못 뒤집고, **×1.5에서 처음으로
  실조회 기반 계정이 1위로 올라선다**. 상위권 그 외 이동은 ±5계단 이내로 안정적.

| 가중 | beauty_linyas2 (계정 raw / 순위) | soft.lynaomi (계정 raw / 순위) |
|---|---|---|
| ×3 (현행) | 93.95 / 1위 | 91.18 / 2위 |
| ×2 | 91.27 / 1위 | 90.97 / 2위 |
| **×1.5 (채택)** | 89.31 / 2위 | 90.81 / **1위** |

(구 앵커 기준 근사 — 앵커 재적합 후 경계선 순위는 다소 움직일 수 있다.)

## 3. 산식 변경

`analytics.hype_score_raw()`(02_serving.sql)의 참여 항을 릴스·피드 두 분기 모두:

```
likes + comments×3   →   likes + comments×w
w = app_setting 'analytics.hype-comment-weight' (COALESCE 기본 1.5)
```

- 키 관용구는 가중치 계열(wr·we)과 동일한 순수 COALESCE 관용구 — 0은 "댓글 배제"라는
  유효 운영값이므로 NULLIF 방어를 두지 않는다(e0·f0의 NULLIF는 0 나눗셈 방어라 성격이
  다름). **미설정이면 함수 내 COALESCE 기본값, Flyway 시드 없음, 단일 소스는 함수 기본값.**
- 운영에서 키에 `3`을 넣으면 현행 동작으로 즉시 롤백된다(뷰 재적용·재배포 불필요).
  단, 앵커 기본값은 w=1.5 기준으로 교체되므로 w=3 롤백은 "순위 응급 복원"용이지
  척도까지 완전 복원하려면 뷰 원복이 필요하다 — 롤백 시 이 한계를 인지할 것.

## 4. 앵커 재적합 동반 (필수)

가중 하향으로 Q 분포 전체가 아래로 이동한다. 앵커를 그대로 두면 "p50→45점" 백분위
의미가 깨지고 전 계정 점수가 일괄 하락하므로, 기존 절차
`analytics/check/hype-anchor-refit.sh`(재현 절차 보존 이유는 v3 스펙 §5-2)로
**w=1.5 기준 운영 코퍼스**에서 4종 앵커를 재산출해 함수 COALESCE 기본값을 교체한다:

1. 콘텐츠 Q 앵커 `hype-anchor-q-{reels,feed}-{p05,p50,p90,p99}` (hype_score_raw)
2. 출력 앵커 `hype-anchor-out-*` (hype_score_output — 랭킹 경로 실측 분포 기준)
3. 계정 정수 앵커 `hype-anchor-acct-*` (hype_account_score)
4. 계정 소수 앵커 `hype-anchor-acct-precise-*` (hype_account_score_precise —
   sum/고정분모 모수, 07-31 스펙 기준과 동일)

재적합 순서 주의: 1 → 2 → 3·4 순으로 의존한다(출력 앵커는 새 Q의 raw 분포를,
계정 앵커는 새 출력값의 계정 평균 분포를 입력으로 쓴다).

## 5. 파급 범위

- `hype_score_raw` 공유 지점 전부가 일제히 변한다: `v_contents`(hype_score·
  hype_score_precise), `v_content_metric_snapshots`, `v_account_summaries`(avg_hype_raw·
  avg_hype_score·avg_hype_precise_raw·avg_hype_score_precise), 마이크로 계정 뷰(20).
- 과거 v3의 "정수 점수 값 불변" 계약과 달리 이번에는 **표시 점수 전체가 의도적으로
  변한다** — 프론트 공지는 불필요(점수 척도 의미는 백분위로 동일 유지).
- 참여율 표시(avg_er_pct·median_er_pct 등)는 ×3을 쓰지 않으므로 불변.
- DB 스키마 변경 없음(함수·뷰 CREATE OR REPLACE만) — Flyway 마이그레이션·
  expand-contract·migration-guard 해당 없음.

## 6. 검증·배포

- SQL 하니스: `analytics/test/02_*.test.sql` 기대값 갱신 + **롤백 경로 테스트**
  (키에 3을 넣으면 참여 항이 현행 산식과 일치하는지) 추가.
- 승격 전 staging에서 발굴 목록 top-20을 운영 현행과 비교, §2 시뮬레이션 예측과
  부합하는지 확인.
- 배포는 정규 경로(develop→staging→main). CD가 뷰를 raw DB에 자동 적용하고 야간
  미러가 반영 시점을 정한다 — 랭킹 변화는 미러 갱신 시각에 일괄 반영된다.

## 7. 한계 (별도 트랙 후보)

- 댓글 가중 하향만으로는 **초다작 우위 구조**(하루 2~3개 게시로 감쇠 무력화)는 그대로
  남는다. 게시 빈도 반영은 명시된 제품 결정이므로 손대려면 결정 번복이 선행돼야 한다.
- 상단 매핑 압축(상위권 98~100 밀집)도 그대로다 — 순위에는 영향 없는 표시 문제.
- 댓글 품질(품앗이 vs 실수요) 판별은 하지 않는다 — ×1.5에서도 댓글비율이 극단적인
  계정은 여전히 상위권 잔류 가능(실측: beauty_linyas2 2위).
