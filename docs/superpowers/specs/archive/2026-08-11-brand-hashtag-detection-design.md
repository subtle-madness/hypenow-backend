# 브랜드 해시태그 감지 — 해시태그-only 언급 게시물 수집 설계

> 상태: ✅ 구현됨 (2026-08-11 설계 확정·같은 날 구현 — 끌리메 실데이터 PoC 19콜 + 시뮬레이션 검증. 브랜치 feat/brand-hashtag-detection, 구현 중 개정: 직접태그 플래그→출처 배지(§4-4)·판정 컨텍스트에 brand biography 추가·조기 종료는 이번 실행 저장분 제외)

## 0. 한 줄 요약

브랜드 계정을 **직접 태그하지 않고 해시태그로만 언급한** 게시물을 레이더에 추가한다.
태그 셋은 등록 데이터에서 **전자동 유도 3종**(브랜드명·계정명 루트·전체 계정명), 발견 게시물은
**hypenow 유저 종속** 피드 하나로, 노출은 **AI 관련 판정분만**. 보강(프로필·댓글) 콜 없이
스윕 ~3콜/일/브랜드.

## 1. 배경·근거 (2026-08-11 끌리메 PoC 실측)

기존 브랜드 감지는 `/v2/user/tag/medias`(유저태그 열거) 단일 경로라, 해시태그만 달고 계정
태그는 안 한 게시물이 전부 사각지대다. 끌리메(에스테틱 프랜차이즈, 계정 33개) 실측:

- **고객 UGC의 38~67%가 계정 태그 없이 해시태그만 사용** (#끌리메 38%, #cclime 67%) — 순증분 실재.
- 해시태그 recent 스트림의 **71~87%는 자사(본사·지점·직원) 게시물** — 자사 필터가 노이즈 컷의 본체.
- 순수 고객 해시태그-only 중 관련 65% / 무관·판별불가 35%. 무관에는 **이름 충돌**(동명 타업종 —
  도자기 식기 "끌리메" 실관측)이 포함되어 키워드 규칙으로는 못 거른다 → LLM 분류 필요 근거.
- 스트림 특성: 페이지당 27건, 페이지 경계는 대체로 시간 역순(섹션 내부만 랭킹 섞임).
  **#끌리메 1페이지 ≈ 25일치**, 대형 브랜드도 일 유입 ~1건.
- 경쟁 리서치(Archive/archive.com): 유저 등록 태그 + 비소급 + "100% 아님" 명시가 업계 표준 계약.
  노이즈 처리는 수동. 우리 차별점 = **유입 단계 AI 분류 + 계정 연동 불필요 + 등록 즉시 소급 백필**.

## 2. 태그 셋 — 전자동 유도 3종, 유저 입력 없음

| 태그 | 유도원 | 예 (끌리메) |
|---|---|---|
| 브랜드명 | `app.users.company_name` — **`user_type = 'brand'`인 경우만** (타 유형은 대행사명 등이라 부적합) | #끌리메 |
| 계정명 루트 | username에서 상용 접미사(`_official`·`.official`·`_kr` 등) 제거 | #cclime |
| 전체 계정명 | username 그대로 | #cclime_official (실사용 263건 확인) |

- 중복 유도(루트=전체 등)는 자연 합침. 시드 분석·media_count 검증·태그 관리 UI 없음 —
  추후 "태그 추가" 확장 여지만 스키마에 남긴다.
- 유도 시점은 등록 커밋 시(§6) — company_name·username이 이미 손에 있어 **콜 0**.

## 3. 스윕 — 조기 종료 페이지네이션

- 태그별 `/v2/hashtag/medias/recent` 를 페이지 순으로 열거. **상한 4페이지.**
- **조기 종료**: 가져온 페이지 안에 이미 감지된 게시물이 나타나면 페이지 내 신규는 전부
  처리하고 **페이지네이션만 중단**(콜은 페이지 단위라 중간 중단은 무의미). 과반 조건 등
  정교화 없음 — p2에 신규가 숨는 케이스는 미고려로 확정(2026-08-11 사용자 결정).
- 효과: 등록 직후 첫 스윕은 상한까지 돌아 **과거 2~3개월 소급 백필**(1페이지 ≈ 25일치 실측),
  평상시엔 태그당 1페이지로 수렴.
- 일일 스윕은 기존 브랜드 스윕 크론(운영 KST 새벽) 뒤에 직렬로 붙는다. 전역 동시 콜 상한
  구조(워커 6 + 스윕 1 + 등록 1 = 8) 불변.

## 4. 필터 파이프라인 (순서 고정)

1. **최근창**: `taken_at`이 기존 브랜드 윈도우(90일)를 벗어나면 버림.
2. **자사 계열 제외**: 게시자 username에 **제외 문자열이 포함**되면 제외.
   - 기본값 = 계정명 루트 자동 등록(예: "cclime" — 지점·직원 계정 일괄 커버).
   - **제외 문자열 목록은 유저가 관리 가능**(추가·삭제) — 억울한 제외는 유저가 직접 푼다.
   - 끌리메 시뮬레이션: 101건 중 77건(76%) 제외, 오탐·미탐 각 0건.
3. **중복 제거**: 기존 감지분(유저태그·해시태그 불문)이면 스킵. 조기 종료 판정 재료 겸용.
4. **직접태그 제외**: 응답 `usertags`에 등록 계정이 있으면 제외 — 기존 유저태그 스윕의 영역
   (해시태그 파이프라인은 순수 "해시태그-only" 담당). 피드 배지는 판정이 아니라 **출처로
   자연 결정**: 유저태그 스윕 유래 = "직접 태그", 해시태그 스윕 유래 = "해시태그 발견".
5. **멘션 신호**: usertags엔 없고 캡션 @멘션에만 등록 계정이 있으면 파이프라인에 남기되
   **AI 분류 스킵, 관련 확정** (유저태그 스윕이 못 잡는 케이스 — 시뮬레이션 2건 실증).
6. **AI 분류** (나머지 신규만): 브랜드 컨텍스트(브랜드명·업종·태그 셋)를 주고 캡션 기준
   **관련 / 무관 / 불확실** 판정. 핵심 역할은 이름 충돌 방어. 필터 후 볼륨이 브랜드당
   일 수 건이라 비용 무시 가능.

## 5. 저장·노출

- **종속 = hypenow 유저**(등록 브랜드 계정). 그룹 엔티티·계정 귀속 규칙 없음 — 현 1계정
  정책에선 유저=계정 1:1이고, 다계정 확장 시에도 피드는 하나·중복은 게시물 단위로 접힌다.
- **판정 결과 포함 전량 저장**(무관·불확실도) — 중복 제거 키가 되어 익일 재분류를 막고,
  추후 보강·재판정 시 재수집이 불필요. 저장은 08-06 격리 원칙에 따라 기존 스냅샷·댓글
  파이프라인 비접촉의 **경량 신규 테이블**을 제안(발견 링크 + 스트림 페이로드 발췌 + 판정
  — 상세 스키마는 구현 계획에서).
- **노출은 관련 판정만**. 무관·불확실 둘 다 비노출(2026-08-11 보수 확정).
- **보강 보류**: 게시자 프로필·댓글 콜 없음. 표시는 스트림 응답 필드만
  (게시자 username·캡션·시각·좋아요/댓글 수).

## 6. 시작 시점

기존 등록 흐름(was `registerBrand` → monitoring 동기 검증 → 커밋)에 편승:

1. 등록 커밋 시 태그 셋 유도(콜 0).
2. 등록 직후 비동기 백필 큐(`brandBackfillExecutor`)에서 유저태그 백필에 이어 해시태그
   첫 스윕(상한 4페이지 — 태그 3종 × 4 = 최대 12콜 1회성). 기존 "수집 준비 중" 판별
   (`last_swept_on` null) 재사용.
3. 이후 일일 스윕 크론 합류.

## 7. 비용

| 작업 | 콜 |
|---|---|
| 등록 백필 (1회) | 최대 12콜 (태그 3 × 4페이지) |
| 일일 스윕 | ~3콜 (태그 3 × 1페이지, 조기 종료 수렴) |
| 보강 | 0 (보류) |
| LLM 분류 | 브랜드당 일 수 건 — 무시 가능 |

콜당 $0.0006 기준 브랜드당 월 ~$0.05 수준 — 기존 감지(월 ~$0.20) 대비 소폭.

## 8. 계약·한계 (명시)

- **best-effort 발견**: 해시태그 스트림은 IG 랭킹이 섞여 전수 열거 불가 — "왜 이 게시물 안
  잡혔어요" 방어선. Archive도 동일 계약을 명시하는 업계 표준.
- **@멘션-only 사각지대**: 캡션 @멘션만 있는 게시물(해시태그·유저태그 없음)은 역방향 조회
  경로가 없다(Hiker에 멘션 열거 엔드포인트 부재 확인). 수용.
- 스토리 미커버(계정 연동 전제라 우리 모델 밖). 소급은 스트림이 닿는 범위(~2-3개월)까지만.
- 지점 고유 태그(#끌리메삼성점 등) 폐기로 인한 손실은 실측상 소수(관련 26건 중 3건이
  구조적 미커버, 나머지는 공용 태그 병기로 일일 스윕이 커버) — 수용.
