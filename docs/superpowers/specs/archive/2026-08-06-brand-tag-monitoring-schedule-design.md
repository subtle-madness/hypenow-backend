# 브랜드 태그 게시물 모니터링 — 수집 스펙·주기·비용 설계

> 상태: ✅ 구현됨 · ⚠️ 부분 대체 (2026-08-06 — 수집 대상·경로·게이팅은 이 문서대로 구현. 단 **주기(§3 트래킹 3일→매일 전량)·게시자 외 저장 스키마·브랜드 프로필 갱신(§2 등록 1회→매일)은 같은 날 설계 재논의로 개정** — 정본은 DECISIONS 08-06 개정 행 · 트랙 [MON-BT](../../../tracks/MON-BT-브랜드-태그-모니터링.md))

## 0. 한 줄 요약

브랜드 회원이 가입하면 그 계정에 **태그된 게시물**을 자동 모니터링한다. 수집은
`/v2/user/tag/medias` **열거 단일 경로**(단건 게시물 조회 없음), 감지 매일 · 트래킹 3일 1회,
윈도우 90일 & 105개. 브랜드 1계정당 등록 일회 ~$0.10, 상시 월 ~$0.20(콜당 $0.0006 기준).

## 1. 배경·전제

- 대상: 회원가입한 브랜드 계정(스케일 가정 2,000개). **가입 시점에 자동 시작, 탈퇴까지 지속.**
- 수집원: HikerAPI 단가 콜당 $0.0006 (비교 기준으로 $0.001도 병기).
- 실측 근거: 2026-08-06 라이브 실측 12콜 —
  [findings §11](../../plans/2026-07-28-monitoring-hiker-findings.md) 참조. 요지:
  - `/v2/user/tag/medias`는 **페이지당 21건**(8콜 전부 동일), `next_page_id` 페이지네이션.
  - **릴스 조회수(`play_count`·`ig_play_count`)가 열거 응답에 상시 실린다** — 프로필 열거
    (`/v2/user/medias`)와 다른 결정적 차이. 조회수 때문에 단건 콜을 붙일 이유가 없다.
  - 정렬은 **태그된 시점 순**이라 `taken_at` 비단조 — 옛 게시물이 최신 페이지에 끼어든다.
  - 실고객급 5브랜드 태그 유입: 0.4~2.3건/일(4곳), 캠페인 중 21건/일(1곳, lizda).
  - 단건 조회는 열거 대비 **추가로 주는 지표가 없다**(저장·리포스트 당첨률은 오히려 낮음,
    08-04 findings) — 단건 배제 결정의 근거.

## 2. 수집 대상

| 대상 | 항목 | 방법 |
|---|---|---|
| 브랜드 계정 | 팔로워 수·소개글 (+pk 해석) | `/v2/user/by/username` — 등록 시 1콜 |
| 태그 게시물 | **조회수(릴스만)·좋아요 수·댓글 수** + 메타(code·타입·작성자·작성시각·캡션) | `/v2/user/tag/medias` 열거만. **단건 조회 없음** |
| 댓글 내용 | 게시물당 **최대 45개**(15개/콜 × 3콜) | `/v2/media/comments` — 아래 게이팅 규칙 |
| 게시자(인플루언서) | 프로필(팔로워 수 등) | `/v2/user/by/id` — 새 게시물 감지 시 1회 + **등장 시 stale 갱신**(트래킹에서 그 작성자 게시물이 다시 보일 때 마지막 조회 30일 경과면 재조회 — 일괄 배치 아님, 2026-08-06 확정) |

- 댓글 게이팅: **열거의 `comment_count`가 저장값보다 클 때만** 댓글 콜을 낸다. 등록 시점엔
  저장값 0이므로 자연히 "댓글 1개 이상인 게시물만" 수집된다(실측 보유율 ~50~60%,
  시딩 UGC 위주 브랜드는 24%까지 낮음). 댓글 숨김(작성자가 댓글 기능 끔) 게시물은 미수집.
- 저장·공유·리포스트 수(복권 3종)는 **DB에는 적재하되 FE에는 미노출**(2026-08-06 확정) —
  열거 응답에 세션 복권으로 어차피 실려 와 추가 콜 0. 적재 시 기존 monitoring 모듈의
  캐리포워드·0 캐리 규칙 재사용(§6). 서빙 계약에는 포함하지 않는다.
- 열거의 작성자 `user` 객체에는 username·pk·이름·프로필사진·비공개·인증 배지가 공짜로
  실려 오고, **팔로워 수·소개글은 없다** — 이것이 게시자 프로필 콜이 별도로 필요한 이유.

## 3. 주기

| 작업 | 주기 | 콜 |
|---|---|---|
| 감지 (새 태그 게시물 확인) | **매일** | 열거 1페이지 1콜 |
| 트래킹 (확보 게시물 지표 갱신) | **3일에 1번** | 열거 5페이지(105개 커버) — 이날 감지는 트래킹이 겸함(**추가 콜 없음**) |
| 댓글 재수집 | 트래킹 시 | `comment_count` 증가 게시물만, 최신부터 읽다 기지 댓글에서 중단 |
| 게시자 재조회 | 등장 시 30일 stale 갱신 | 해당 작성자당 1콜 (활동 없는 작성자에겐 콜 없음) |

일 단위 콜 패턴(브랜드 1개): 평일 1콜, 트래킹일 5콜(+댓글·게시자 변동분).

## 4. 범위 (슬라이딩 윈도우)

- **게시물**: 최근 **90일 & 최대 105개** — 등록 백필도, 이후 추적도 같은 기준.
  105개(=5페이지)를 트래킹 깊이와 일치시켜 "백필한 게시물 전부가 계속 갱신됨"을 보장한다.
  윈도우에서 밀려나면(90일 경과 또는 106번째로 밀림) 추적 자연 종료.
- **계정**: **탈퇴까지** (2026-08-06 확정 — 휴면 완화 없음. 비용이 실제 문제 되면 재론).

## 5. 등록(백필) 절차 — 브랜드 1계정

1. 브랜드 프로필 1콜 (pk·팔로워 수·소개글)
2. 태그 열거 최대 5페이지 — 90일 이내만 담고, **페이지 전체가 90일보다 오래됐으면 중단**
   (소급 태그로 옛 게시물이 끼므로 "오래된 글 1건 발견 즉시 중단"은 금지)
3. 백필 게시물의 게시자 전원 프로필 조회 (~30~85명, pk 중복 제거)
4. 댓글 있는 게시물만 댓글 수집 (평균 1.2콜/건)

## 6. 구현 유의 (실측에서 나온 제약)

- **페이지당 21건을 하드코딩하지 말 것** — IG가 정하는 값. "목표 개수를 채울 때까지
  `next_page_id` 추종"으로 구현한다.
- **감지는 code 기준 dedupe** — 정렬이 태그 시점 순이라 "본 적 있는 code 만나면 중단"이
  아니라 "**페이지 전체가 기지(旣知)일 때 중단**"이어야 소급 태그를 놓치지 않는다.
- 저장·리포스트를 담기로 한다면 세션 복권이므로 기존 monitoring 모듈의 캐리포워드·
  0 캐리 로직 재사용(08-04·08-05 DECISIONS 참조). 조회수 fb 합산 규칙(08-03)도 동일 적용 대상.
- 게시자 프로필은 **브랜드 간 전역 캐시**(같은 인플루언서가 여러 브랜드를 태그) — crawler DB
  기존 프로필 5.4만 건도 재사용 후보.

## 7. 비용

브랜드 1계정, 평균 유입 2건/일 기준(괄호: 조용한 브랜드 ~ 캠페인 중 브랜드):

| | 콜 수 | $0.0006/콜 | $0.001/콜 |
|---|---|---|---|
| 등록(일회) = 1+5+~85+~70 | ~161 (54~220) | **$0.097** | **$0.161** |
| 월간 = 감지30+트래킹40+게시자(54+~40)+댓글~130 | ~295 (130~950) | **$0.177** | **$0.295** |
| 하루 평균 | ~9.8 (4.3~32) | $0.0059 | $0.0098 |

2,000계정 환산: 상시 **월 ~$354**($0.0006) / ~$590($0.001), 등록 누적 일회 ~$193/$322.
(게시자 재조회를 "등장 시 stale 갱신"으로 확정한 수치 — 일괄 배치였다면 월 +$0.03/브랜드)

비용 구성비: 게시물 지표(감지+트래킹)는 월 $0.042로 ~24%뿐. **게시자 프로필(~1/3)과
댓글(~45%)이 지배 항** — 추가 절감이 필요하면 댓글 재수집 임계 상향이 남은 손잡이다.
감지·트래킹 쪽은 이미 바닥이라 절감 여지가 없다.

## 8. 후속 확정 (2026-08-06, 같은 날 사용자 확정 — 미결 아님)

- **게시자 재조회 = 등장 시 stale 갱신**: 트래킹에서 그 작성자 게시물이 다시 보일 때
  마지막 조회 30일 경과면 재조회. 월 1회 일괄 배치 아님(활동 없는 작성자에게 콜 안 씀).
- **복권 3종(저장·공유·리포스트)은 DB 적재, FE 미노출**: 열거가 주는 값을 버리지 않고
  담되(콜 0 추가), 서빙 계약·화면에는 포함하지 않는다.
- **휴면 완화 없음**: 계정 추적은 탈퇴까지가 정본.

구현 범위(수집 파이프라인만인지, was 조회 API·FE 계약까지인지)는 이 스펙이 정하지
않았다 — 구현 세션이 착수 전 확인할 유일한 항목.
