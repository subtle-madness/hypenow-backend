# 유사 인플루언서 유사도 v2 설계

> 상태: 🟢 활성 · 설계 확정(2026-07-28) — 1단계 구현 대상, 2단계(어휘 통제)는 보류. 구현 계획은 plans/ 참조

## 1. 배경과 문제

`GET /v1/influencers/{id}/similar`(PR #149, 미머지)는 traits(LLM 자유 서술 성향 태그 3~5개)의
Jaccard로 유사도를 계산한다. 운영 실측(2026-07-28, 계정 7,025개 기준)으로 확인된 문제:

- trait 인스턴스 28,387개에 **고유값이 5,847개** — 67%(3,939개)가 단 1회 등장.
  표기 흔들림("뷰티 정보 공유"/"뷰티 정보"/"정보 공유", "릴스 중심"/"릴스 콘텐츠"/"릴스 중심 운영")이
  매칭 실패로 직결되어 Jaccard가 사실상 난수에 가깝다.
- 태그 3~5개라 유사도 해상도가 계단식(0/17/33/60%…).
- 최소 유사도 컷이 없어 교집합 0인 계정도 팔로워 근접순으로 끼워 6명을 무조건 채운다.

## 2. 결정 요약

| # | 항목 | 결정 | 단계 |
|---|---|---|---|
| ① | 어휘 통제 | 고정 택소노미 + 프롬프트 주입 방향은 확정, **어휘 구성·규모는 보류** — 초안 44개는 표현력 하락 우려로 반려. 카테고리·태그라인 변경이 반영된 분석 데이터가 쌓인 뒤 재결정 | 2단계(보류) |
| ② | 점수 구성 | `0.6 × 태그 Jaccard + 0.4 × 카테고리 믹스 히스토그램 교집합`. 후보 스코프는 같은 주 카테고리 유지(경계 완화 안 함) | 1단계 |
| ③ | 표시 | 유사도 %·점수·순위 **화면 노출 전면 제거** — 점수는 내부 정렬용만. API 응답에서 matchPct 계열 필드 삭제 | 1단계 |
| ④ | 인원 | 최대 **10명** (기존 6명에서 변경) | 1단계 |
| ⑤ | 최소 컷 | 혼합 점수 하한 **0.30** — 미달이면 10명 미만으로 노출 (운영 분포 dry-run 실측 확정, §3) | 1단계 |

검토했으나 채택하지 않은 안: 후처리 정규화 사전(신규 변형이 계속 생겨 유지보수가 영구 과제),
emergent 대표값 접기(군집 경계 불안정), IDF 가중 Jaccard(고정 어휘에선 복잡도 대비 이득 작음),
임베딩(인프라 비용 — 최후 수단 유지).

**1단계 효과 한계(의도된 것)**: 자유 서술 traits에서는 Jaccard 성분이 거의 0이라 1단계 점수는
사실상 카테고리 믹스 중심으로 동작한다. 그래도 현행(난수성 Jaccard 정렬 + 무조건 6명 채움)보다
낫고, 2단계에서 어휘가 통제되면 태그 성분이 자연히 살아난다 — 점수식·컷·API는 재변경 불필요.

## 3. 1단계: findSimilar 점수식 (was)

```
score = 0.6 × Jaccard(traits_a, traits_b)            -- 양쪽 DISTINCT, 기존 산식 유지
      + 0.4 × Σ min(share_a(c), share_b(c))          -- account_category_stats 비중 벡터의
                                                     --   히스토그램 교집합, c = 카테고리
```

- 믹스 성분은 analysis DB 파생 뷰 `account_category_stats`(V35) 사용 — was는 읽기만(경계 준수).
  믹스 데이터가 없는 쪽이 있으면 성분 0.
- 가중치 0.6/0.4와 컷값은 SQL 상수 — 화면 비노출 내부값이라 app_setting 채널은 두지 않는다(YAGNI).
- `WHERE score >= 컷` 후 `ORDER BY score DESC, abs(팔로워 차) ASC LIMIT 10`.
- **컷 = 0.30 (실측 확정, 2026-07-28 운영 dry-run)**: 샘플 30계정 × 동일 카테고리 전 후보 기준
  후보쌍 점수 p05=0.240 / p50=0.400 / p95=0.486, 기준 계정별 10위 점수 최솟값=0.400.
  0.30은 정상 패널(10명)을 전혀 줄이지 않으면서 믹스 교집합 0.75 미만 + 태그 무겹침 후보만
  걸러낸다. '미분류' 피어(믹스 없음)는 태그 Jaccard ≥ 0.5가 아니면 빈 패널 — 의도된 동작.
  2단계 어휘 통제 후 분포가 우상향 이동하면 재점검.
- 응답 DTO에서 matchPct(overlapN/unionN) 제거. 프론트 미착수 상태라 스펙에서 필드 자체를 삭제.

## 5. 2단계(보류): 어휘 통제 — 방향만 기록

아래는 방향 합의만 된 상태로, **착수 트리거는 "카테고리·태그라인 변경이 반영된 분석 데이터 확보 후
사용자 재결정"**이다. 어휘 규모는 44개 초안보다 커질 전망(표현력 유지가 반려 사유).

- 어휘: analysis DB `trait_taxonomy` 테이블, `beauty_taxonomy`(V30)처럼 analytics Flyway로 시드.
  `GeminiAccountSynthesizer`(및 Anthropic 합성기) INSTRUCTIONS의 traits 항목을 "어휘 내 선택"으로
  변경하고 로더로 주입. 어휘 밖 출력은 저장 시 드롭. `Synthesis.VERSION`은 올리지 않는다
  (기존 문구 재합성 회피가 배치 매핑을 택한 이유).
- 기존 데이터 이행: analytics 어드민 원샷 잡 — 고유 trait 값 수집 → LLM 배치 매핑(~100개/콜) →
  `account_analyses.traits` in-place UPDATE(중복 제거, 매핑 불가 값 제거). 감사 테이블
  `trait_canon_log(raw_value, canon_value, mapped_at)`에 전체 매핑 보존, dry-run 후 실행.
  매핑 후 태그 0개 계정은 빈 배열 그대로(믹스 성분으로 후보 유지).
- 배포 순서: analytics(시드·프롬프트) → 매핑 잡 dry-run·실행 → (필요시) was 컷 상수 재조정.
  1단계와 달리 순서 엄수 — 매핑 전 신어휘 분석이 섞이는 기간은 짧게.
