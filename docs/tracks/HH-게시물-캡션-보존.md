## 내용

조사 착수 전제("게시물 캡션 원문이 DB에 없다")가 오판이었음을 정정 — 캡션은 raw jsonb에 실재했고, 도달 경로가 5~7단 jsonb 표현식뿐이라 `raw_post_detail`(0행)·`raw_discovery_post`(DISCOVERY 전용)를 조인해 "없다"고 오판한 전력이 있다(07-30). 정본 추출식은 `analytics/views/00_base.sql`의 `v_base_reel_item`·`v_base_timeline_item`에 원래부터 있었다. 진짜 결함은 `MediaItemExtractor`가 캡션을 파싱조차 하지 않아 사장된 것(유실이 아니라 추출 부재). `content_caption`(V23 — `content_id` PK·최신 1건·`source` provenance·RESTRICT FK, 96MB. 압축·보존기간 제한 없음: pglz 실측 이득 7%뿐) 신설 + 추출기가 세 소스(릴스 jsonb·피드 jsonb·SELF_GQL 내장 타임라인) 파싱 + 라이브 배선(`CollectJob`·`ReelsJob`) + `CAPTION_BACKFILL` 원샷 잡(인스타 호출 0회·라이브와 동일 파서·`app_setting` 워터마크 재개·어드민 `/ui` 수동 트리거, 스케줄 미등록). **캡션 3-상태 계약**: 행 부재=미확인 / `''`=확인된 무캡션 / 그 외=원문. 무캡션 표현이 소스마다 다름(운영 실측, 세 소스 모두 키 부재 0건): V2_CLIPS `"caption": null`(24/2,905=0.83%) · V1_MEDIAS `caption_text: ""`(23/2,393) · SELF_GQL `edges: []`(23/3,542). 운영 실측: ENUMERATION 캡션 커버리지 REELS 98.9%/FEED 88.7%. **어떤 analytics 뷰도 읽지 않는 현역 소스 `HIKER_V1_MEDIAS`**(9,691행·1,062MB·07-18~)에 갇힌 FEED 캡션 약 6,240건(표본 40 중 33=82.5%)을 재크롤 0원으로 건짐. **저장 측면만 해소** — analytics 뷰는 여전히 jsonb를 직접 읽고 `HIKER_V1_MEDIAS`를 무시하므로 복원분이 뷰·랭킹·LLM 판정엔 미반영(서빙 반영은 analytics 트랙 후속). 참조 코드 없는 `raw_post_detail`(0행) DROP 동반(V24). 리뷰가 잡은 결함 3건(전부 되돌려 실패 확인한 회귀 테스트 있음): ①백필 `try/catch`가 트랜잭션 안 → Postgres가 COMMIT을 조용히 ROLLBACK으로 치환하는데 워터마크만 전진 → 청크 200페이지 영구 유실 ②`capturedAt` 공유 단정이 공용 `Clock.fixed` 때문에 무의미 → 무한 tick 생성기로 재설계 ③빈 문자열이 실제 캡션을 덮는 경로(라이브가 `now()`라 항상 백필을 이김) → 3-상태로 차단 — [specs/2026-07-30-caption-preservation-design.md](../superpowers/specs/2026-07-30-caption-preservation-design.md) [plans/2026-07-30-caption-preservation.md](../superpowers/plans/2026-07-30-caption-preservation.md)
